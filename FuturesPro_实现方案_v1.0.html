第1章 项目概述

1.1 项目背景

FuturesPro 是一套专为专业期货交易者打造的 AI 驱动量化交易平台。系统融合了实时行情分析、智能交易信号识别、策略回测与管理、风险控制等核心功能，旨在为用户提供一站式的期货量化交易解决方案。

随着金融科技的快速发展，传统的手工交易方式已经难以满足专业交易者对速度、精度和效率的要求。FuturesPro 通过引入人工智能和机器学习技术，实现了交易信号的智能识别与市场情绪的自动分析，帮助交易者在复杂多变的市场环境中做出更加科学的决策。

系统采用前后端分离架构，前端基于 React + TypeScript 构建现代化交互界面，后端使用 Python + FastAPI 提供高性能 API 服务，数据层采用 PostgreSQL + TimescaleDB + Redis 的组合方案，确保数据的可靠性与实时性。

1.2 核心目标

  1. 模块化系统架构：实现7大核心模块（仪表盘、实时交易、回测系统、交易雷达、策略管理、交易历史、账户中心），各模块独立开发、灵活组合，支持按需扩展。
  2. 专业交易工具：提供实时行情推送、K线图表、订单簿、深度图等专业交易工具，满足日内交易、波段交易等多种交易场景需求。
  3. AI 智能分析：集成 AI 智能交易信号识别、市场情绪分析、技术形态检测等功能，利用机器学习模型辅助交易决策，提升交易胜率。
  4. 策略研究与回测：提供完整的策略回测引擎，支持历史数据回测、参数优化、风险分析，帮助用户验证和改进交易策略。
  5. 完善的风控体系：建立多层风险控制机制，包括单笔限额、日累计限额、持仓集中度限制、账户安全验证等，保障用户资金安全。

表现层 React + TypeScript + Ant Design + ECharts + Tailwind CSS
▼
接口层 FastAPI + Nginx + WebSocket (Socket.io) + RESTful API
▼
业务逻辑层 Python 服务模块（交易引擎 / 策略引擎 / 回测引擎 / AI信号引擎 / 风控引擎）
▼
数据访问层 SQLAlchemy ORM + Redis Cache + Redis Streams + Celery 任务队列
▼
数据存储层 PostgreSQL + TimescaleDB + Redis + MinIO

第7章 核心业务逻辑设计

7.1 交易执行流程

交易执行引擎负责处理用户下单请求，经过风控校验后提交到交易所，并实时跟踪订单状态。

Step 1
订单接收与验证
接收下单请求，验证参数合法性
→
Step 2
风控校验
检查资金充足性、持仓限制、风控规则
→
Step 3
订单提交
通过券商API提交订单到交易所
→
Step 4
状态跟踪与回调
实时跟踪订单状态，成交后更新持仓和资金

详细说明：

  1. 订单接收与验证：接收前端提交的下单请求，使用 Pydantic 模型验证请求参数（合约代码、方向、开平、价格、数量等），确保数据格式正确、字段完整。
  2. 风控校验：调用风控引擎对订单进行多层校验，包括：可用资金是否充足、是否超过单笔限额、是否超过日累计限额、持仓集中度是否超限等。校验不通过则返回具体错误信息。
  3. 订单提交：风控校验通过后，通过券商网关API将订单提交到交易所。记录订单状态为 PENDING，冻结相应保证金。
  4. 状态跟踪与回调：通过 WebSocket 或轮询方式跟踪订单状态变更。订单成交后，更新订单状态为 FILLED，计算成交盈亏，更新持仓信息（开仓则新增持仓，平仓则减少持仓并计算盈亏），释放冻结资金，通过 WebSocket 推送状态变更到前端。

7.2 策略引擎流程

策略引擎负责运行用户创建的交易策略，根据实时行情数据触发交易信号并自动执行交易。

Step 1
策略加载与初始化
加载策略配置，初始化运行环境
→
Step 2
行情数据订阅
订阅策略关联合约的实时行情
→
Step 3
信号计算与执行
根据行情数据计算交易信号并执行
→
Step 4
绩效跟踪与记录
记录交易结果，更新策略绩效指标

详细说明：

  1. 策略加载与初始化：从数据库加载策略配置（类型、参数、关联合约等），初始化策略运行环境，包括技术指标计算器、状态管理器等组件。策略状态设置为 RUNNING。
  2. 行情数据订阅：通过 Redis Streams 订阅策略关联合约的实时行情数据流。当有新的行情数据到达时，触发策略计算逻辑。
  3. 信号计算与执行：根据策略类型和参数，对最新行情数据计算技术指标，判断是否满足交易条件。满足条件时生成交易信号，经过风控校验后自动提交订单执行。
  4. 绩效跟踪与记录：记录策略产生的每笔交易，实时计算策略绩效指标（累计收益、胜率、最大回撤等）。当策略触发停止条件（如达到最大亏损限额）时，自动暂停策略运行。

7.3 回测引擎流程

回测引擎使用历史数据模拟策略运行，评估策略的历史表现和风险指标。

Step 1
回测配置解析
解析策略参数、时间范围、资金设置
→
Step 2
历史数据加载
从TimescaleDB加载指定合约的历史K线数据
→
Step 3
逐Bar模拟执行
按时间顺序逐根K线模拟策略运行
→
Step 4
绩效指标计算
计算收益率、回撤、夏普比率等指标
→
Step 5
结果存储与展示
保存回测结果，生成报告

详细说明：

  1. 回测配置解析：解析用户提交的回测配置，包括策略ID、合约代码、回测时间范围、初始资金、手续费率、滑点设置等参数。
  2. 历史数据加载：从 TimescaleDB 中加载指定合约在回测时间范围内的历史K线数据（含开盘价、最高价、最低价、收盘价、成交量）。数据按时间升序排列。
  3. 逐Bar模拟执行：按时间顺序逐根K线模拟策略运行。对每根K线，先计算技术指标，然后根据策略逻辑判断是否产生交易信号，模拟下单和成交过程，更新虚拟持仓和资金。通过 WebSocket 实时推送回测进度。
  4. 绩效指标计算：回测完成后，计算各项绩效指标，包括：总收益率、年化收益率、最大回撤、夏普比率、Sortino比率、胜率、盈亏比、最大连续亏损次数等。
  5. 结果存储与展示：将回测结果、交易记录、资金曲线数据保存到数据库。生成回测报告，支持PDF导出。前端通过图表组件展示回测结果。

7.4 AI信号引擎流程

AI信号引擎结合技术指标分析和机器学习模型，自动识别市场交易机会并生成交易信号。

Step 1
数据采集与预处理
采集多品种行情数据，计算技术指标
→
Step 2
特征工程
构建多维度特征向量
→
Step 3
模型预测与信号生成
ML模型预测 + 技术指标规则融合
→
Step 4
信号评分与过滤
计算信号强度，过滤低质量信号
→
Step 5
信号推送与存储
推送高质量信号，存入数据库

详细说明：

  1. 数据采集与预处理：从 Redis 缓存和 TimescaleDB 采集全市场品种的最新行情数据。使用 TA-Lib 计算技术指标（MA、EMA、MACD、RSI、KDJ、BOLL、ATR等），对数据进行标准化和缺失值处理。
  2. 特征工程：基于原始行情和技术指标，构建多维特征向量，包括：价格趋势特征（均线排列、趋势强度）、动量特征（RSI、MACD柱状图）、波动率特征（ATR、布林带宽度）、成交量特征（量比、OBV）、形态特征（K线形态识别结果）等。
  3. 模型预测与信号生成：将特征向量输入预训练的机器学习模型（随机森林/XGBoost），预测未来价格方向和概率。同时，基于技术指标规则（如金叉死叉、超买超卖、突破等）生成规则信号。将ML信号和规则信号进行融合，生成综合交易信号。
  4. 信号评分与过滤：对每个信号计算综合强度评分（0-100分），考虑因素包括：ML模型预测概率、技术指标共振数量、信号时效性、历史同类型信号胜率等。过滤掉评分低于阈值的低质量信号。
  5. 信号推送与存储：将高质量信号存入数据库，通过 WebSocket 实时推送到前端交易雷达页面。用户可在雷达页面查看信号详情，并选择是否据此进行交易。

风控引擎对每笔交易进行多层风险检查，确保交易行为在用户设定的风险范围内。

详细说明：

  1. 风控规则加载：从数据库加载用户的风控设置（单笔限额、日亏损限额、持仓集中度限制等），同时加载系统级默认风控规则（最小下单量、最大持仓量等）。
  2. 多层风控校验：对订单进行四层校验：
    • 资金校验：检查可用资金是否足够支付保证金和手续费
    • 限额校验：检查单笔委托金额是否超过最大限额、当日累计亏损是否超过日亏损限额
    • 集中度校验：检查单一合约持仓占比是否超过最大集中度限制
    • 频率校验：检查下单频率是否异常，防止恶意刷单
  3. 风控决策：根据校验结果做出决策：
    • 通过：所有校验通过，允许订单提交
    • 拒绝：触发硬性风控规则（如资金不足、超过限额），直接拒绝订单
    • 需确认：触发软性风控规则（如接近限额），要求用户二次确认
  4. 记录与告警：记录所有风控校验日志（包括通过和拒绝的记录），用于事后审计和分析。当触发重要风控事件（如接近日亏损限额、频繁被拒）时，通过 WebSocket 推送告警通知到前端。

第9章 非功能性需求

9.1 性能要求

  • ● API响应时间：常规接口响应时间 < 200ms（P95），复杂查询接口 < 500ms（P95），WebSocket消息推送延迟 < 100ms。
  • ● 并发处理能力：系统支持至少 500 个并发WebSocket连接，API服务支持 1000 QPS 的请求处理能力。
  • ● 数据查询性能：K线数据查询支持百万级数据量的秒级响应，利用TimescaleDB的时间分区和压缩特性优化查询性能。
  • ● 前端渲染性能：首屏加载时间 < 2秒，K线图表渲染支持10万根K线的流畅展示，页面交互响应时间 < 100ms。

9.2 安全要求

  • ● 身份认证：采用 JWT + Refresh Token 双Token机制，Access Token 有效期30分钟，Refresh Token 有效期7天，支持Token刷新和主动失效。
  • ● 密码安全：用户密码使用 bcrypt 算法加密存储（cost factor >= 12），支持密码强度校验和定期更换提醒。
  • ● 数据传输加密：所有API通信强制使用 HTTPS (TLS 1.2+)，WebSocket通信使用 WSS 协议。
  • ● API访问控制：基于RBAC（基于角色的访问控制）模型，API密钥支持细粒度权限设置（读/写/交易），接口级权限校验。
  • ● 输入验证与防注入：所有用户输入经过 Pydantic 严格验证，SQL查询使用参数化查询防止SQL注入，前端输出进行XSS转义。
  • ● 频率限制：API接口实施请求频率限制（基于Redis Token Bucket算法），登录接口限制5次/分钟，常规接口限制60次/分钟。
  • ● 审计日志：记录所有关键操作（登录、下单、修改风控设置、API密钥操作等）的审计日志，日志不可篡改，保留期限不少于180天。

9.3 可用性要求

  • ● 系统可用性：系统整体可用性目标为 99.9%（月度），计划外停机时间每月不超过43分钟。
  • ● 数据备份：PostgreSQL数据库每日全量备份 + 实时WAL归档，备份保留30天。支持跨区域备份存储。
  • ● 容灾恢复：支持数据库主从切换，RTO（恢复时间目标）< 15分钟，RPO（恢复点目标）< 5分钟。
  • ● 监控告警：Prometheus + Grafana 实现服务监控，关键指标异常时自动触发告警（邮件/钉钉/短信），告警响应时间 < 5分钟。
  • ● 优雅降级：当部分服务不可用时，核心交易功能优先保障，非核心功能（如AI信号、雷达扫描）可降级或暂时关闭。

9.4 可扩展性

  • ● 水平扩展：后端服务支持无状态水平扩展，通过增加实例数量提升处理能力。WebSocket连接支持分布式部署（Redis Pub/Sub 广播）。
  • ● 模块化设计：各业务模块（交易、回测、信号、风控）独立解耦，支持独立升级和替换。新增策略类型或交易所接入仅需实现对应接口。
  • ● 数据层扩展：TimescaleDB支持自动分区管理，历史数据自动压缩。Redis支持集群模式扩展缓存容量。
  • ● 插件机制：策略引擎和AI信号引擎支持插件式扩展，新增技术指标、ML模型或策略类型可通过插件方式集成，无需修改核心代码。
